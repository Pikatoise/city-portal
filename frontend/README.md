# CityPortal frontend

Angular 22 application with a Node.js SSR host. Public routes use SSR. Account and staff routes render in the browser and remain placeholders until their stage 1 workflows are implemented.

Use Node.js 26.8.1 and npm 11 or later. Run commands from this directory; on Windows use `npm.cmd` if PowerShell blocks `npm.ps1`.

```sh
npm ci
npm start
```

The development server opens at `http://localhost:4200`; `/api/` requests proxy to the API at `http://localhost:5080`. The Docker Compose proxy supplies the same HTTPS origin for the frontend and API. See [local development](../docs/DEVELOPMENT.md) for the whole stack.

```sh
npm run build
npm test -- --watch=false
npm run format:check
npm run api:check
npm run serve:ssr:city-portal
```

The production server listens on port 4000 by default. Set `PORT` to change it. Do not expose it directly in production; use the same-origin reverse proxy.

The SSR host allows `localhost` and `127.0.0.1`. Configure `NG_ALLOWED_HOSTS` for a different deployment hostname. Set `TRUST_PROXY_HEADERS=true` only behind the trusted reverse proxy, which must replace forwarded headers; Compose keeps this service internal.

The checked-in `openapi.json` comes from the API, and `src/app/api/` is generated by `ng-openapi-gen`. To regenerate from the snapshot, use `npm run generate:api`. To download the running API contract and regenerate, use:

```sh
npm run refresh:api
npm run refresh:api -- http://localhost:5080/openapi/v1.json
```

Do not edit generated files. Commit the OpenAPI snapshot and generated changes together with their API implementation.
